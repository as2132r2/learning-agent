# Day35第6步：独立讲解与查漏补缺

本步骤不增加产品能力。目标是让你能够脱离逐行照读，解释一个请求的完整执行过程。

## 练习方式

```bash
# 显示实际验收证据与6个问题
python day35/python/day35_explain_project.py

# 自己讲完后查看参考答案
python day35/python/day35_explain_project.py --answers

# 将自己的讲解保存为待复核记录
python day35/python/day35_explain_project.py --practice
```

练习不调用模型，也不自动给自己的回答打通过。保存结果的awaiting_human_review表示尚待复核；运行脚本成功不代表已经能独立设计Agent。

## 六个必讲主题

1. 从CLI输入到计算节点、工具循环、最终回答。
2. AIMessage.tool_calls与ToolMessage的区别，以及6条消息来源。
3. session_id、flow_id、note_id与SQLite恢复。
4. RAG证据、Prompt、消息历史和无证据拒答。
5. 快照绑定、interrupt重放、批准后写入。
6. 幂等、错误分类、重试上限与跨库一致性边界。

## 根据已实现代码核查的易混点

- 当前路由是关键词规则；不是另一次LLM路由调用。
- 聊天模型与知识回答复用普通llm，计算绑定工具，精排另有模型请求；对象角色不等于多个独立模型服务。
- 模型提出工具调用不等于工具已执行；结果由本机ToolNode生成。
- 检索证据不追加成聊天消息，但作为状态字段仍可写入checkpoint。
- 最终知识节点只使用本轮问题和证据，未实现基于历史的独立问题改写。
- 保存笔记请求由CLI协调独立审批图，并非聊天图自己挂起。
- /status显示聊天状态；/flows用于查看审批。
- latest是最近更新的流程，不保证仍在等待批准。
- 私有会话编号不等于身份认证；本项目不宣称公网多用户授权已完成。
- 批准保存后如果聊天事件记录失败，应以审批状态与实际文件核对，不应再次盲目写入。
